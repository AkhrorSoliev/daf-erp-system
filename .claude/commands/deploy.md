# Deploy to Vercel + Create PR

Automate the full deployment workflow. The user may optionally provide `$ARGUMENTS` as a hint, but the commit message and branch name should always be auto-generated based on the actual changes.

## Instructions

Execute the following steps **sequentially**. Print each step with its icon before running. If any step fails, print ❌ with the error and stop immediately.

### 📦 Step 1: Analyze changes
Run `git status` and `git diff` to understand what has changed. Identify all modified, added, and deleted files. Stage all relevant files (skip `.env*`, credentials, secrets). Use `git add` with specific file names — avoid `git add -A`.

Print: `📦 Staging changes...`

If there are no meaningful changes to deploy (ignoring `.claude/` directory), print `❌ No changes to deploy.` and stop.

### 💾 Step 2: Generate commit message
Based on the staged changes, generate a clear, concise commit message in English that accurately describes what was changed. The message should:
- Start with a verb (Add, Update, Fix, Remove, Refactor, etc.)
- Be specific about what changed (e.g., "Add login page with form validation" not "Update files")
- Be max 72 characters for the subject line

```bash
git commit -m "<auto-generated commit message>"
```
Print: `💾 Committing: "<message>"`

### 🔀 Step 3: Create branch
Derive the branch name from the auto-generated commit message. Convert it to a kebab-case slug (max 5 words, lowercase, no special chars).

Example: commit message "Add inventory dashboard page" → `deploy/add-inventory-dashboard-page`

```bash
BRANCH_NAME="deploy/<slug>"
git checkout -b "$BRANCH_NAME"
```
Print: `🔀 Creating branch <branch-name>...`

**Note:** Since we already committed on `main`, after creating the branch we are on the new branch with the commit included.

### 🚀 Step 4: Push to origin
```bash
git push -u origin "$BRANCH_NAME"
```
Print: `🚀 Pushing to origin...`

### 🌐 Step 5: Deploy to Vercel
```bash
cd client && vercel --prod --yes
```
Wait for deployment to complete. Capture the production URL.

Print: `🌐 Deploying to Vercel...`
After success: `🌐 Deployed → <production-url>`

### 🔗 Step 6: Create Pull Request
```bash
gh pr create --base main --head "$BRANCH_NAME" --title "<commit message>" --body "$(cat <<'EOF'
## Summary
<brief description of changes>

## Deploy
✅ Successfully deployed to Vercel
🔗 <production-url>

---
🤖 Auto-deployed with `/deploy`
EOF
)"
```
Print: `🔗 PR created → <pr-url>`

### ✅ Step 7: Cleanup
```bash
git checkout main
git pull origin main
git branch -D "$BRANCH_NAME"
```
Print: `✅ Done! Switched back to main. Local branch deleted.`

## Final Summary
Print a summary box:
```
┌─────────────────────────────────┐
│  ✅ Deployment Complete!        │
│  🔗 PR:     <pr-url>           │
│  🌐 Deploy: <production-url>   │
│  🔀 Branch: deleted            │
└─────────────────────────────────┘
```
