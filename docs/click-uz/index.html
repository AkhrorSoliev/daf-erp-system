CLICK Hujjatlar

CLICK to'lov tizimi bilan integratsiya qilish uchun to'liq texnik hujjatlar.

Ushbu hujjatlar to'plamida tovar va xizmatlar yetkazib beruvchilarning (jumladan, onlayn do'konlarning) billing tizimlari va CLICK tizimi o'rtasidagi o'zaro aloqa tartibi tavsiflangan.

Mavjud integratsiya usullari

#UsulTavsif
1SHOP-APICLICK tizimi ta'minotchining API manziliga so'rov yuboradi (Prepare va Complete bosqichlari)
2To'lov tugmasiFoydalanuvchini CLICK to'lov sahifasiga yo'naltirish yoki sahifada to'lov qabul qilish
3Merchant-APITa'minotchi CLICK API ga aktiv so'rov yuboradi (invoice yaratish, token bilan to'lov va h.k.)
4Telegram to'lovlariTelegram bot orqali to'lov qabul qilish
5Mobil integratsiyaAndroid va iOS ilovalar orqali deeplink bilan to'lov

Atamalar va ta'riflar

  • CLICK tizimi — mobil telefon (USSD/SMS-portal) yoki internet (WEB/mobil WEB) orqali turli xizmatlar uchun to'lov amalga oshirish imkonini beruvchi tizim.
  • Ta'minotchi — foydalanuvchilarga tovar va xizmatlar sotuvchi yuridik shaxs.
  • Foydalanuvchi — CLICK tizimiga ulangan jismoniy shaxs.
  • Ta'minotchi xizmatlari — sotishga taklif etiladigan tovarlar va xizmatlar.
  • Ta'minotchining billing tizimi — ta'minotchi va xaridor o'rtasidagi hisob-kitob va to'lov operatsiyalarini elektron tarzda yuritish imkonini beruvchi infratuzilma.

SHOP-API — Umumiy ma'lumot

Umumiy qoidalar

Ushbu hujjat tovar va xizmatlar ta'minotchilarining (jumladan, onlayn do'konlarning) billing tizimlari va CLICK tizimi o'rtasidagi o'zaro aloqa interfeysi orqali ishlash tartibini tavsiflaydi.

CLICK tizimi orqali onlayn savdo, uyali aloqa operatorlari, internet-provayderlar, naqd pul o'tkazmalari va boshqa xizmatlar uchun to'lovlarni amalga oshirish mumkin.

Ishlash tartibi

SHOP-API ikki bosqichli to'lov jarayoniga asoslangan:

  1. Prepare (Tayyorlash) — CLICK tizimi ta'minotchining serveriga so'rov yuborib, buyurtma/hisobni tekshiradi va to'lovni zaxiralaydi.
  2. Complete (Yakunlash) — To'lov muvaffaqiyatli amalga oshirilgandan so'ng, CLICK tizimi ta'minotchiga tasdiqlash so'rovini yuboradi.
Muhim: CLICK tizimi HTTP/HTTPS POST so'rovlari orqali ta'minotchining API manziliga murojaat qiladi. Ta'minotchi ushbu manzilni o'z serverida sozlashi kerak.

Jarayon diagrammasi

SHOP-API ketma-ketlik diagrammasi

1. Foydalanuvchi → CLICK: To'lov boshlash

2. CLICK → Ta'minotchi API: Prepare so'rovi (action=0)

3. Ta'minotchi API → CLICK: Prepare javobi (merchant_prepare_id)

4. CLICK: Kartadan pul yechish

5. CLICK → Ta'minotchi API: Complete so'rovi (action=1)

6. Ta'minotchi API → CLICK: Complete javobi (merchant_confirm_id)

7. CLICK → Foydalanuvchi: To'lov natijasi

SHOP-API — So'rov

To'lov jarayoni ikki bosqichda amalga oshiriladi. Barcha so'rovlar HTTP/HTTPS POST usulida ta'minotchining API interfeysiga yuboriladi.

1-bosqich: Prepare (Tayyorlash) — action = 0

Ushbu bosqichda CLICK tizimi to'lovni tasdiqlash uchun ta'minotchining billing tizimiga so'rov yuboradi.

1click_trans_idbigintCLICK tizimidagi tranzaksiya identifikatori

4merchant_trans_idvarcharTa'minotchidagi buyurtma/hisob identifikatori
5amountfloatTo'lov summasi (so'mda)
6actionintHarakat turi: 0 — Prepare bosqichi
7errorintHolat kodi (0 = muvaffaqiyatli)
8error_notevarcharXatolik tavsifi
9sign_timevarcharImzo vaqti. Format: YYYY-MM-DD HH:mm:ss
10sign_stringvarcharTekshiruv imzosi (quyida ko'ring)

sign_string hisoblash (Prepare)

md5(click_trans_id + service_id + SECRET_KEY + merchant_trans_id + amount + action + sign_time)

Javob parametrlari

#ParametrTuriTavsif

Tekshiruv talablari

Ta'minotchi quyidagilarni tekshirishi shart:
  • Buyurtma/hisob mavjudligi va to'g'riligi
  • Ta'minotchining tovar/xizmat yetkazib berish imkoniyati
  • To'lov summasining to'g'riligi
Onlayn savdo uchun: Ko'rsatilgan raqamli buyurtma uchun so'rov kelganda, ta'minotchi tegishli mahsulotni boshqa xaridorlar tomonidan "ushlab qolinishining" oldini olish uchun zaxiralashi kerak.

2-bosqich: Complete (Yakunlash) — action = 1

Kartadan pul muvaffaqiyatli yechilgandan so'ng CLICK tizimi ushbu so'rovni yuboradi.

Javob parametrlari

#ParametrTuriTavsif

Complete bosqichi xatolik kodlari

  • error = 0 — To'lov muvaffaqiyatli. Mablag'lar yechildi. Ta'minotchi tovar/xizmat yetkazib berishi shart.
  • error <= -1 — Bekor qilish. Mablag'lar yechilmadi. Ta'minotchi zaxirani bekor qilishi va error = -9 bilan javob berishi kerak.

Muhim eslatmalar

Takroriy to'lovdan himoya: Ta'minotchi o'zining billing tizimida avval tasdiqlangan to'lov uchun (bir xil click_trans_id bilan) takroriy to'lovdan himoya qo'yishi shart.
Xizmat ko'rsatishda xatolik: Agar mablag'lar kartadan muvaffaqiyatli yechilgandan so'ng xizmat ko'rsatishda xatolik yuzaga kelsa, ta'minotchi "Complete" so'roviga "muvaffaqiyatli" deb javob berishi va keyin "to'lovni bekor qilish" so'rovini yuborishi kerak.

SHOP-API — Testlash

Ishlab chiqish jarayonida CLICK API interfeysini testlash va xatoliklarni tuzatish uchun maxsus dasturiy ta'minot ishlatiladi.

Test dasturi

Dastur CLICK tizimidagi harakatlarni emulyatsiya qiladi. Dasturni ZIP fayl sifatida yuklab olish mumkin. U ta'minotchiga sozlamalarni moslashtirish va oldindan belgilangan stsenariylarni ketma-ket testlash imkonini beradi.

Konfiguratsiya maydonlari

#ParametrTuriTavsif
1Prepare URLvarcharPrepare so'rovlari uchun API endpoint manzili
2Complete URLvarcharComplete so'rovlari uchun API endpoint manzili
3service_idintCLICK ro'yxatdan o'tish vaqtida berilgan xizmat identifikatori
4merchant_user_idintCLICK ro'yxatdan o'tish vaqtida berilgan xizmat identifikatori
5secret_keyvarcharImzo shakllantirilishi uchun maxfiy kalit
6merchant_trans_idvarcharOnlayn do'kon tizimidagi to'lov identifikatori
7prepare/confirm_idfaqat o'qishSkript bajarilishi davomida avtomatik to'ldiriladi

Testlash tartibi

  1. Konfiguratsiya ma'lumotlarini kiriting
  2. Ochiladigan menyudan stsenariyni tanlang
  3. Testni boshlang
  4. So'rov/javob ma'lumotlarini test jurnali oynasida ko'ring
  5. Muvaffaqiyatli testlar "passed" holati bilan ko'rsatiladi
Muhim: Barcha skriptlar muvaffaqiyatli o'tishi shart!

Ro'yxatdan o'tishni yakunlash

Barcha testlar yakunlangandan so'ng, "Generate Report" tugmasini bosing. Bu sozlamalarni tekshirish va CLICK ro'yxatdan o'tish serveriga yuborish jarayonini boshlaydi.

Muvaffaqiyatli ro'yxatdan o'tish xabari: "Registration Status report: Registration completed successfully!"

Ta'minotchilar muvaffaqiyatli ro'yxatdan o'tishni http://merchant.click.uz orqali tekshirishlari mumkin.

Eslatma: Dasturda ko'rsatilgan URL test dasturi uchun mavjud bo'lishi kerak (mahalliy kompyuterda ham bo'lishi mumkin).

Merchant-API — Umumiy ma'lumot

Umumiy shartlar

Ushbu interfeys ta'minotchi tomonidan internet orqali foydalanuvchiga hisob-faktura (invoice) so'rovlarini joylashtirish uchun ishlatiladi.

SHOP-API dan farqli o'laroq, Merchant-API da ta'minotchi CLICK tizimiga so'rov yuboradi (aksincha emas).

Atamalar

  • CLICK to'lov tizimi — mobil telefon (USSD/SMS) yoki internet (WEB/Mobil) kanallari orqali to'lov amalga oshirish imkonini beruvchi tizim.
  • Ta'minotchi — foydalanuvchilarga tovar va xizmatlar sotuvchi yuridik shaxs.
  • Foydalanuvchi — CLICK to'lov tizimiga ulangan jismoniy shaxs.
  • Ta'minotchi xizmatlari — xizmatlar va tovarlar.

Jarayon diagrammasi

Merchant-API ketma-ketlik diagrammasi

1. Ta'minotchi → CLICK API: Invoice yaratish

2. CLICK → Foydalanuvchi: To'lov so'rovi (push-xabar)

3. Foydalanuvchi → CLICK: To'lovni tasdiqlash

4. CLICK: Kartadan pul yechish

5. Ta'minotchi → CLICK API: To'lov holatini tekshirish

6. CLICK API → Ta'minotchi: Holat javobi

Merchant-API — So'rov

Ulanish va autentifikatsiya

API bazaviy manzil: https://api.click.uz/v2/merchant/

Ro'yxatdan o'tish uchun kerakli ma'lumotlar

  • merchant_id — ta'minotchi identifikatori
  • service_id — xizmat identifikatori
  • merchant_user_id — ta'minotchi foydalanuvchi identifikatori
  • secret_key — maxfiy kalit (sir saqlanishi shart!)

Auth sarlavhasi formati

Auth: merchant_user_id:digest:timestamp

digest = sha1(timestamp + secret_key)
timestamp = UNIX vaqt belgisi (10 xonali, soniyalarda)

Kerakli sarlavhalar

  • Accept: application/json
  • Content-Type: application/json
  • Auth: 123:356a192b7913b04c54574d18c28d46e6395428ab:1519051543
Xavfsizlik: secret_key parametri maxfiy hisoblanadi va uning xavfsizligini saqlash uchun xizmat ta'minotchisi to'liq javobgar. secret_key ni oshkor qilish ma'lumotlaringiz buzilishiga olib kelishi mumkin.

CLICK Pass

CLICK Pass — QR kod orqali to'lov qabul qilish imkonini beradi.

Autentifikatsiya

API bazaviy manzil: https://api.click.uz/v2/merchant/ 
Auth: merchant_user_id:digest:timestamp
digest = sha1(timestamp + secret_key)
timestamp = UNIX vaqt belgisi (10 xonali)

Foydalanuvchi nomi — bu botni topish uchun ishlatiladigan manzil. Talablar:

Jonli rejim

To'lovni testlash jarayoni

1-qadam: Hisob-faktura yaratish

Xaridor ta'minotchi botiga murojaat qilib, tovarlarni tanlaydi. Bot mahsulot/xizmat tavsifi, to'lov summasi va yetkazib berish ma'lumotlari bilan hisob-faktura tuzadi.

sendInvoice usuli hisob-fakturalarni yaratadi, provider_token parametrini talab qiladi. Bitta bot turli foydalanuvchilar yoki tovarlar uchun bir nechta turli tokenlardan foydalanishi mumkin.

Hisob-fakturalar faqat shaxsiy xabar foydalanuvchilariga ko'rsatiladi, guruh yoki kanallarga emas.

2-qadam: Buyurtmani tekshirish va tasdiqlash

To'lov boshlanganda, Bot API pre_checkout_query maydonini o'z ichiga olgan yangilanishni yuboradi. Bot 10 soniya ichida answerPrecheckoutQuery orqali javob berishi yoki tranzaksiyani bekor qilishi kerak.

Xatolik javoblari oddiy foydalanuvchilarga tushunarli bo'lishi kerak. Masalan: "Kechirasiz, bu mahsulot mavjud emas, ehtimol boshqa mahsulotlarimiz sizni qiziqtirishi mumkin?"

3-qadam: To'lovni amalga oshirish

Bot tasdiqlangandan so'ng, Telegram to'lov tizimiga tranzaksiyani yakunlash so'rovini yuboradi. Muvaffaqiyatli to'lov success_payment xabarini ishga tushiradi. Foydalanuvchilar istalgan vaqtda to'lov tafsilotlarini ko'rsatuvchi kvitansiyani oladi.

Jonli rejimga o'tish

Testlar yakunlangandan so'ng, @BotFather da /mybots → bot tanlash → Settings → Payments → CLICK Uzbekistan → "Connect CLICK Terminal LIVE" ni tanlang.

Avtorizatsiya uchun bank shartnomasi tuzilgandan keyin berilgan hisob ma'lumotlari talab qilinadi.

Olingan tokenda :LIVE: mavjud bo'ladi (masalan: 123:LIVE:XXXX).

Bu tokenni uchinchi shaxslarga bermang!

Jonli rejim talablari

  • Ikki faktorli autentifikatsiya: Botni boshqaruvchi Telegram hisobi uchun qat'iy tavsiya etiladi
  • Nizolar bo'yicha javobgarlik: Bot egalari nizolar yoki kelishmovchiliklar yuzaga kelganda to'liq javobgarlikni o'z zimmalariga oladi

Mobil integratsiya

Android va iOS mobil ilovalar uchun CLICK to'lov tizimi bilan integratsiya usullari.

Umumiy yondashuv

Bizning mobil ilova ikkala platformada ham to'lov uchun havolalarni (deeplink) ushlaydi. Agar ilova o'rnatilmagan bo'lsa, tizim brauzeri ochiladi va to'lov veb-sayt orqali amalga oshiriladi.

Android integratsiyasi (Kotlin)

val url = "https://my.click.uz/services/pay/" +
    "?service_id=${serviceId}" +
    "&merchant_id=${merchantId}" +
    "&amount=${amount}" +
    "&transaction_param=${transactionParam}"

val i = Intent(Intent.ACTION_VIEW)
i.data = Uri.parse(url)
startActivity(i)

iOS integratsiyasi (Swift)

if let url = URL(string: "https://my.click.uz/services/pay/?service_id=\(serviceId)&merchant_id=\(merchantId)&amount=\(amount)&transaction_param=\(transactionParam)") {
    UIApplication.shared.open(url)
}

To'lovdan keyingi jarayon

Muvaffaqiyatli to'lovdan so'ng ilova o'zini yopadi. Ishlab chiquvchilar tranzaksiya parametri yordamida onStart yoki onRestart usullarida ma'lumotlarni yangilashlari mumkin.

Agar return_url parametri kiritilgan bo'lsa, tizim to'lov tugagandan keyin (xatolik holatlarini ham o'z ichiga olgan holda) ushbu havolani Intent sifatida chaqiradi.

Android SDK

Chuqurroq integratsiya uchun CLICK Android Mobile SDK kutubxonasini taklif etadi. Bu kutubxona billing tizimiga ega va ega bo'lmagan ta'minotchilarni qo'llab-quvvatlaydi.

Eslatma: Billing tizimiga ega ta'minotchilar o'z ilova serverlarida SHOP-API ni amalga oshirishlari kerak.
