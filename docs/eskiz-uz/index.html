Eskiz.uz SMS API

Eskiz.uz — O'zbekiston hududida (va xalqaro) SMS xabarlar yuborish uchun SMS shlyuz (SMS gateway). Ushbu hujjatlar to'plami notify.eskiz.uz REST API bilan integratsiya tartibini, autentifikatsiya, shablon moderatsiyasi, SMS yuborish va hisobotlarni tavsiflaydi.

Eslatma: Ushbu hujjat DaF Sprachzentrum ERP tizimi uchun tayyorlangan ichki ma'lumotnoma bo'lib, eskiz.uz rasmiy Postman hujjatlari asosida o'zbek tiliga moslashtirilgan. Payme va Click hujjatlari bilan bir xil uslubda tuzilgan.

Asosiy ma'lumotlar

ParametrQiymat
Asosiy URL (Base URL)https://notify.eskiz.uz/api
ProtokolREST (JSON / multipart/form-data)
AutentifikatsiyaBearer token (JWT)
Token yashash muddati~30 kun (PATCH /auth/refresh bilan yangilanadi)
Telefon formati998XXXXXXXXX (12 raqam, + belgisisiz)
Standart jo'natuvchi (from)4546 (test nik). Brend nik moderatsiyadan o'tishi kerak
ShablonIshlab chiqarishda har bir matn oldindan moderatsiyadan o'tishi shart
Test matniBu Eskiz dan test (shablonsiz yuborish mumkin)

Integratsiya bosqichlari

  1. Ro'yxatdan o'tish — my.eskiz.uz kabinetida hisob ochish, balans to'ldirish.
  2. Token olish — kabinetdagi email + parol bilan POST /auth/login orqali JWT token olish.
  3. Brend nik — o'z nomingiz (masalan DaFZentrum) uchun ariza berib, moderatsiyadan o'tkazish.
  4. Shablon — yuboriladigan har bir matn ko'rinishini POST /user/template orqali tasdiqlatish.
  5. Yuborish — POST /message/sms/send (yoki send-batch) orqali SMS jo'natish.
  6. Holatni kuzatish — callback_url yoki status_by_id orqali yetkazish holatini olish.

Bosh sahifa › Boshlash › Ro'yxatdan o'tish

Ro'yxatdan o'tish va kalit

Eskiz API'dan foydalanish uchun avval my.eskiz.uz kabinetida hisob ochiladi. API kaliti emas, balki email + parol orqali token olinadi.

Kerakli ma'lumotlar

Ma'lumotQayerdan olinadi
emailKabinetga kirgan email
passwordKabinet → Sozlamalar → API bo'limidagi maxsus API parol (kabinet kirish parolidan farq qiladi)
Diqqat: API uchun ishlatiladigan parol — bu kabinetning API bo'limidagi maxsus paroldir, oddiy login paroli emas. Uni o'zgartirsangiz, eski token bekor bo'lmaydi, lekin yangi token olish uchun yangi parol kerak bo'ladi.

Balans

SMS yuborish uchun kabinetda balans bo'lishi kerak. Balansni GET /user/get-limit orqali tekshirish mumkin. Har bir SMS narxi GET /user/prices orqali ko'riladi.

Maxfiylik

Muhim: email, password va olingan token ni hech qachon frontend (brauzer/mobil ilova) kodiga joylashtirmang. Faqat backend (server) tomonida, environment o'zgaruvchilarida saqlang.
Bosh sahifa › Boshlash › Token hayot sikli

Token hayot sikli

Eskiz API Bearer JWT token ishlatadi. Token taxminan 30 kun amal qiladi, so'ng yangilanishi kerak.

Bosqichlar

  1. Olish: POST /auth/login → data.token qaytadi.
  2. Ishlatish: har bir so'rovga Authorization: Bearer <token> sarlavhasini qo'shing.
  3. Yangilash: token eskirishidan oldin PATCH /auth/refresh (eski token bilan) → yangi token qaytadi.

Tavsiya etilgan strategiya (backend)

Tokenni Redis da keshlang (masalan 25 kunlik TTL bilan). Har so'rovda qayta login qilmang. 401 Unauthorized javobi kelganda — bir marta avtomatik login qilib, tokenni yangilab, so'rovni qayta yuboring (retry-on-401).

Token muddati tugaganda

Muddati o'tgan token bilan so'rov yuborilsa, API 401 bilan javob qaytaradi. Bunda /auth/refresh ishlamasligi mumkin (token allaqachon yaroqsiz) — bu holda qaytadan /auth/login qiling.

# 1. Token olish
curl -X POST https://notify.eskiz.uz/api/auth/login \
  -F "email=vash@email.uz" \
  -F "password=API_PAROL"

# Javob: { "data": { "token": "eyJ0eXAiOiJ..." } }

# 2. Tokenni ishlatish
curl https://notify.eskiz.uz/api/auth/user \
  -H "Authorization: Bearer eyJ0eXAiOiJ..."

# 3. Yangilash
curl -X PATCH https://notify.eskiz.uz/api/auth/refresh \
  -H "Authorization: Bearer eyJ0eXAiOiJ..."

Shablon moderatsiyasi

Eng muhim qoida: Ishlab chiqarishda (test nikdan tashqari) yuboriladigan har bir SMS matni oldindan moderatsiyadan o'tgan shablonga mos kelishi shart. Tasdiqlanmagan matn yuborilsa, SMS jo'natilmaydi (rad etiladi).

Qanday ishlaydi

  1. Yuboriladigan matn ko'rinishini POST /user/template orqali (yoki kabinet orqali) yuborasiz.
  2. Shablon moderation holatiga tushadi va Eskiz operatorlari uni tekshiradi.
  3. Tasdiqlangach, faqat shu matn ko'rinishidagi SMS lar yuboriladi.

O'zgaruvchilar

Shablonlarda o'zgaruvchan qismlar bo'lishi mumkin (ism, parol, kod va h.k.). Eskiz odatda o'zgaruvchilarni qavslar bilan belgilashga ruxsat beradi. Misol:

Hurmatli mijoz, DaF Sprachzentrum tizimiga kirish: login {login}, parol {parol}. Sayt: student.dafzentrum.uz

Bunda {login} va {parol} har bir yuborishda haqiqiy qiymatlar bilan almashtiriladi, lekin shablonning umumiy ko'rinishi o'zgarmaydi.

Maslahat: Loyihada ishlatiladigan barcha matnlarni (login ma'lumotlari, parol tiklash kodi, davomat, qarz eslatmasi va h.k.) oldindan ro'yxatlab, hammasini bir vaqtning o'zida moderatsiyaga yuboring. Aks holda kerakli paytda SMS jo'natilmay qoladi.

Test rejimi

Moderatsiyasiz sinab ko'rish uchun standart test nik (4546) bilan aniq Bu Eskiz dan test matnini yuborish mumkin. Boshqa har qanday matn shablon talab qiladi.

Bosh sahifa › Boshlash › Telefon va nik

Telefon va nik formati

Telefon raqami

  • Format: 998XXXXXXXXX — 12 ta raqam, + belgisisiz, 998 mamlakat kodi bilan.
  • To'g'ri: 998991234567
  • Noto'g'ri: +998991234567, 991234567, 8991234567
DaF ERP'da telefon 9 raqamli (+998 prefiksisiz) saqlanadi. Eskizga yuborishdan oldin oldiga 998 qo'shilishi kerak: "998" + student.phone.

Jo'natuvchi nik (from)

  • Standart test qiymati: 4546 — faqat test matni uchun.
  • Brend nik (masalan DaFZentrum) ishlatish uchun uni Eskiz kabinetida ro'yxatdan o'tkazib, moderatsiyadan o'tkazish kerak.
  • Tasdiqlangan niklaringizni GET /nick/me orqali ko'rishingiz mumkin.
  • Nik tasdiqlangach, send so'rovida from maydoniga o'sha nikni yozasiz.

SMS yuborish

Bitta telefon raqamiga SMS yuboradi. Javobda qaytgan id — bu request_id bo'lib, holatni kuzatishda ishlatiladi.

Sarlavhalar

So'rov parametrlari (form-data)

ParametrTuriMajburiyTavsif

messageStringHaXabar matni (tasdiqlangan shablonga mos)
fromStringYo'qJo'natuvchi nik. Standart 4546; brend nik uchun o'zingiznikini yozing

curl -X POST https://notify.eskiz.uz/api/message/sms/send \
  -H "Authorization: Bearer <token>" \

  -F "from=4546"

Javob misoli

{
    "id": "59bf10a2-aba8-4694-8fd5-0be20102a580",
    "message": "Waiting for SMS provider",
    "status": "waiting"
}

callback_url

Agar callback_url berilsa, Eskiz yetkazish holati o'zgarganda quyidagi formatda POST so'rov yuboradi:

{
  "request_id": "UUID",
  "message_id": "4385062",
  "user_sms_id": "vash_ID_zdes",
  "country": "UZ",
  "phone_number": "998991234567",
  "sms_count": "1",
  "status": "DELIVRD",
  "status_date": "2021-04-02 00:39:36"
}
request_id — bu send, send-batch va send-global javobidagi id maydonining qiymati. U bilan SMS ni o'z tizimingizdagi yozuv bilan bog'laysiz.

Bosh sahifa › Ma'lumotnoma › DAF ERP integratsiyasi

DAF ERP integratsiyasi bo'yicha eslatmalar

Bu bo'lim — Payme/Click integratsiyasi kabi, DaF Sprachzentrum backend (NestJS + Prisma) tomonida eskiz'ni qanday ulash bo'yicha amaliy tavsiyalar. Kod hali yozilmagan; bu — yo'l xaritasi.

Tavsiya etilgan arxitektura

  • EskizService — token olish/keshlash (Redis, ~25 kun TTL), avtomatik yangilash, send / send-batch chaqiruvlari, 401'da retry.
  • Mavjud SmsService ni kengaytirish: hozir faqat Telegram orqali yuboradi. Unga eskiz kanalini qo'shish.
  • SmsMessage jadvali ga channel (TELEGRAM | SMS) va providerMessageId / requestId ustunlarini qo'shish (callback'ni bog'lash uchun).
  • Webhook — Payme/Click kabi, callback_url uchun ochiq endpoint (masalan POST /api/gateways/eskiz/callback) qo'shib, yetkazish holatini SmsMessage.status ga yozish.

Telefon formatini moslash

DAF ERP'da telefon 9 raqamli saqlanadi. Eskizga yuborishdan oldin:

const mobilePhone = `998${student.phone}`; // 998 + 9 raqam = 12 raqam

Kanal strategiyasi (keyin hal qilinadi)

SMS qachon va qanday yuborilishi (Telegramga zaxira sifatida yoki parallel) keyinchalik hal qilinadi. Bu hujjat faqat eskiz API ma'lumotnomasidir.

Moderatsiya ro'yxati (oldindan tayyorlash)

Quyidagi matn turlarini oldindan shablon sifatida tasdiqlatish kerak bo'ladi:

  • Kirish ma'lumotlari (login + parol)
  • Parolni tiklash (yangi parol yoki kod)
  • Davomat / qarz / to'lov eslatmalari (agar SMS orqali yuborilsa)
