Payme Business Hujjatlar

Payme Business — O'zbekiston hududida bank kartalari orqali to'lovlarni qabul qilish uchun to'lov platformasi. Ushbu hujjatlar to'plamida biznes ta'minotchining tizimlari va Payme Business tizimi o'rtasidagi o'zaro aloqa tartibi tavsiflangan.

Eslatma: Payme Business faqat yuridik shaxslarga taqdim etiladi: yakka tartibdagi tadbirkorlar, xususiy korxonalar, MChJ, AJ, davlat unitar korxonalari, to'liq va kommandit shirkatlar, shuningdek, notijorat tashkilotlar.

Kassa turlari

#Kassa turiTavsif
1Billing bilan kassaMerchant API (JSON-RPC 2.0) orqali sizning billing tizimingizga integratsiya. Onlayn do'konlar uchun qulay.
2Billingsiz kassaSubscribe API orqali chek (receipt) yaratish. Billing tizimi yo'q ta'minotchilar uchun.
3POS kassaUlanishdan so'ng darhol to'lov qabul qilish mumkin. Integratsiya talab qilinmaydi.

Qabul qilinadigan kartalar

  • Uzcard
  • HUMO

Integratsiya usullari

#UsulTavsif
1Merchant APIPayme tizimi ta'minotchining webhook manziliga JSON-RPC 2.0 so'rovlari yuboradi (CheckPerform, Create, Perform, Cancel, Check, GetStatement)
2Subscribe APITa'minotchi Payme API ga so'rov yuboradi (invoice yaratish, kartani tokenlash, to'lash)
3Checkout formaFoydalanuvchini Payme to'lov sahifasiga yo'naltirish (GET URL yoki POST forma)
4To'lov tugmasiVeb-sayt yoki ilovaga o'rnatiladigan tayyor tugma
5Telegram botTelegram bot orqali to'lov qabul qilish
6Mobil deeplinkiOS/Android ilovalar uchun deeplink bilan to'lov

Asosiy atamalar

  • Payme Business — Paycom to'lov tizimining biznes-integratsiya platformasi.
  • Kassa (Касса) — Payme'da yaratilgan onlayn to'lov qabul qilish nuqtasi. Har bir kassa o'z merchant_id va key ga ega.
  • Ta'minotchi (Merchant) — Payme orqali to'lov qabul qiluvchi yuridik shaxs.
  • Billing tizimi — ta'minotchining buyurtmalar, foydalanuvchilar va to'lovlarni yurituvchi ichki tizimi.
  • Chek (Receipt) — Payme'da yaratilgan to'lov hujjati. Subscribe API orqali boshqariladi.
  • Account — ta'minotchi tizimidagi foydalanuvchini aniqlovchi maydon(lar): order_id, user_id, phone va h.k.
  • Tranzaksiya — alohida to'lov operatsiyasi. Payme id va ta'minotchi transaction identifikatorlariga ega.
  • Tiyin — so'mning 1/100 qismi. Payme barcha summalarni tiyinda yuboradi (1 so'm = 100 tiyin).

Kassa ID va kalitni topish

Har bir Payme kassasi ikkita asosiy ma'lumotga ega: Kassa ID (merchant_id) va Kalit (key).

Kassa ID ni topish

  1. Payme shaxsiy kabinetga kiring: https://merchant.paycom.uz
  2. Chap menyudan "Kassalar" (Кассы) bo'limiga o'ting
  3. Kerakli kassani bosing
  4. "Kassa sozlamalari" sahifasida ID maydonini ko'chirib oling (MongoDB ObjectId formatida: 24 ta belgili hex string)
Kassa ID misol: 5e730e8e0b852a417aa49ceb

Kalitni topish

  1. O'sha kassa sozlamalari sahifasida "Kalit" (Ключ) bo'limini toping
  2. Ikki xil kalit bo'ladi:
    • TEST_KEY — sandbox uchun
    • PRODUCTION_KEY — ishlab chiqarish uchun
  3. Kalitni ko'rish uchun "Показать" tugmasini bosing
Xavfsizlik: Kalit maxfiy! Uni ommaviy repositoriya (GitHub, GitLab) ga joylashtirmang. Faqat server tomonidagi .env fayllarida saqlang.

Kalitni qayta generatsiya qilish

Agar kalit oshkor bo'lib qolgan bo'lsa:

  1. Kassa sozlamalarida "Kalitni qayta yaratish" (Перегенерировать ключ) tugmasini bosing
  2. Yangi kalit paydo bo'ladi — eski kalit darhol ishlamay qoladi
  3. Yangi kalitni .env ga joylashtiring va serveringizni qayta ishga tushiring
Kalit qayta yaratilganda, barcha faol pending tranzaksiyalar ishlamay qolishi mumkin. Production'da bu operatsiyani faqat zaruriyat bo'lganda bajaring.

Sandbox (Песочница)

Sandbox — Merchant API implementatsiyasini xavfsiz sinash uchun muhit. Production'ga chiqishdan oldin barcha stsenariylarni shu yerda o'tkazing.

URL https://test.paycom.uz

Testni boshlash uchun kerakli narsalar

  1. Shaxsiy kabinetda veb-kassa yarating
  2. Kassa ID ini oling (merchant_id)
  3. Kassa yaratilgandan so'ng sizga TEST_KEY beriladi
  4. Kassa sozlamalarida Endpoint URL (webhook) manzilingizni ko'rsating

Ikki test stsenariysi

1-stsenariy: tasdiqlanmagan tranzaksiyani yaratish va bekor qilish

Birinchi bosqichda xavfsizlik tekshiruvlari va xatolarni qaytarish to'g'ri ishlashi tekshiriladi.

  • Auth xato → -32504
  • Noto'g'ri summa → -31001
  • Mavjud bo'lmagan account → -31050..-31099
  • CreateTransaction → state=1
  • CancelTransaction → state=-1

2-stsenariy: tasdiqlanga tranzaksiyani yaratish, bajarish va bekor qilish

Birinchi stsenariy muvaffaqiyatli o'tgandan keyin.

  • CheckPerformTransaction → allow=true
  • CreateTransaction → state=1
  • PerformTransaction → state=2
  • CancelTransaction → state=-2 (refund)
Idempotentlik testi: CreateTransaction, PerformTransaction, CancelTransaction metodlariga so'rov ikki marta yuboriladi. Sizning tizimingiz ikkinchi so'rovni birinchisi bilan bir xil natija bilan qaytarishi shart (yangi yozuv YARATMASLIK!).

Merchant API — Protokol

Umumiy qoidalar

Merchant API Payme Business va ta'minotchining billing tizimi o'rtasidagi o'zaro aloqani tavsiflaydi. Ushbu interfeys orqali Payme tizimi ta'minotchiga so'rovlarni yuboradi.

Texnologiya

  • Protokol: JSON-RPC 2.0
  • Transport: HTTP 1.1 POST
  • Shifrlash: TLS / HTTPS (v1.0, v1.1, v1.2)
  • Parametrlar: faqat named (sifatli), positional emas

Asosiy talablar

  • Server HTTPS ni qo'llab-quvvatlashi shart (TLS v1+ da)
  • Har bir javob HTTP 200 OK bilan qaytishi kerak — xato ham 200 ichida error sifatida qaytadi. Boshqa HTTP status → RPC xato -32400
  • Javob kechikmasligi kerak: 10 sekunddan oshsa Payme timeout beradi

Jarayon diagrammasi

Merchant API ketma-ketlik diagrammasi

1. Foydalanuvchi → Payme: Chek ochish (checkout sahifa)

2. Payme → Ta'minotchi: CheckPerformTransaction

3. Ta'minotchi → Payme: allow: true

4. Foydalanuvchi: Kartani kiritadi

5. Payme → Ta'minotchi: CreateTransaction

6. Ta'minotchi → Payme: state: 1

7. Payme: Kartadan pulni ushlab turadi

8. Payme → Ta'minotchi: PerformTransaction

9. Ta'minotchi → Payme: state: 2

10. Payme → Foydalanuvchi: To'lov muvaffaqiyatli

Protokol tuzilishi

Har bir so'rov JSON-RPC 2.0 formatida uchta asosiy maydonga ega:

  • method — metod nomi (CheckPerformTransaction, CreateTransaction va h.k.)
  • params — metod parametrlari (named obyekt sifatida)
  • id — so'rov identifikatori (integer). Javob ham aynan shu id ni qaytaradi.
JSON-RPC jsonrpc: "2.0" maydoni ixtiyoriy — Payme uni talab qilmaydi, lekin qo'shilsa rad etmaydi.

Merchant API — Avtorizatsiya

Payme Merchant API HTTP Basic Auth orqali autentifikatsiya qiladi.

Authorization header formati

Authorization: Basic base64("Paycom:" + MERCHANT_KEY)
  • Login: har doim literal Paycom
  • Parol: kassa kaliti (TEST_KEY yoki PRODUCTION_KEY)
  • Kodlash: base64(Paycom:<KEY>)

Misol

Agar MERCHANT_KEY = "test_key_123" bo'lsa:

Paycom:test_key_123

base64 → UGF5Y29tOnRlc3Rfa2V5XzEyMw==

Authorization: Basic UGF5Y29tOnRlc3Rfa2V5XzEyMw==

To'liq HTTP so'rov misoli

POST /api/payme/webhook HTTP/1.1
Host: example.uz
Content-Type: application/json
Authorization: Basic UGF5Y29tOnRlc3Rfa2V5XzEyMw==

{
  "method": "CheckPerformTransaction",
  "params": {
    "amount": 500000,
    "account": {
      "order_id": "ORD-123"
    }
  },
  "id": 1
}

Auth tekshirish (ta'minotchi tomonidan)

Ta'minotchi har bir so'rovda quyidagi tekshirishi kerak:

  1. Authorization headeri mavjudmi?
  2. U Basic bilan boshlanadimi?
  3. Base64 dekod qilingandan so'ng Paycom:<KEY> formatidami?
  4. KEY siz kutilgan MERCHANT_KEY ga mosmi?

Agar yuqoridagilardan biri bajarilmasa, quyidagi xato qaytariladi:

{
  "error": {
    "code": -32504,
    "message": {
      "ru": "Ошибка авторизации",
      "uz": "Avtorizatsiya xatosi",
      "en": "Authorization error"
    },
    "data": "auth"
  },
  "id": 1
}
Xavfsizlik: Kalitni crypto.timingSafeEqual() yoki shunga o'xshash constant-time compare orqali solishtiring — oddiy === timing attack'ga ochiq.

Merchant API — So'rov formati

HTTP so'rov

  • Metod: POST
  • URL: ta'minotchining webhook manzili (masalan /api/payme/webhook)
  • Content-Type: application/json
  • Authorization: Basic auth (yuqoriga qarang)

JSON-RPC 2.0 so'rov tanasi

MaydonTuriTavsif
methodStringMetod nomi (CheckPerformTransaction, CreateTransaction, PerformTransaction, CancelTransaction, CheckTransaction, GetStatement)
paramsObjectMetod parametrlari (named)
idIntegerSo'rov identifikatori

So'rov misoli

{
  "method": "PerformTransaction",
  "params": {
    "id": "5e730e8e0b852a417aa49ceb"
  },
  "id": 2032
}

Keng tarqalgan params turlari

ParametrTuriTavsif
idStringPayme tranzaksiya identifikatori (24-belgili hex)
timeTimestamp (ms)Unix vaqt, millisekundda
amountIntegerTo'lov summasi tiyinda (1 so'm = 100 tiyin)
accountObjectTa'minotchi tizimidagi foydalanuvchi/buyurtma ma'lumotlari
reasonIntegerBekor qilish sababi (1-10)
from / toTimestamp (ms)Davr boshi va oxiri (GetStatement uchun)

CreateTransaction

Moliyaviy tranzaksiyani yaratish. Payme bu metodni CheckPerformTransaction muvaffaqiyatli o'tgandan so'ng va foydalanuvchi kartani kiritib tasdiqlagach chaqiradi.

So'rov parametrlari

ParametrTuriTavsif

amountAmountSumma (tiyinda)
accountAccountFoydalanuvchi/buyurtma identifikatorlari

Javob parametrlari

ParametrTuriTavsif
create_timeTimestamp (ms)Yaratilgan vaqt (ta'minotchi tizimida)
transactionStringTa'minotchi billing tizimidagi tranzaksiya ID
stateIntegerHar doim 1 (yaratilgan)

Ta'minotchining majburiyatlari

  • Tranzaksiyani doimiy saqlashda saqlash (DB)
  • Account to'g'riligini tekshirish → xatosa -31050..-31099
  • Summa to'g'riligini tekshirish → xatosa -31001

  • Buyurtma ma'lumotlarini to'lov paytida o'zgarmasligini ta'minlash
  • Buyurtma holatini "to'lov kutilmoqda" qilish

Idempotentlik

Muhim: Agar bir xil id bilan CreateTransaction ikkinchi marta kelsa, yangi tranzaksiya YARATILMAYDI — avvalgi create_time, transaction, state qaytariladi. Sandbox testi buni ikki marta yuborib tekshiradi.

Timeout

Tranzaksiya state=1 holatida 12 soat (43 200 000 ms) turadi. Undan keyin avtomatik bekor qilinadi:

  • state → -1
  • reason → 4 (timeout)

PerformTransaction

Tranzaksiyani bajarish — kartadan pulni yechib, buyurtmani to'langan holatga o'tkazish. State 1 → 2.

So'rov parametrlari

ParametrTuriTavsif
idStringPayme tranzaksiya identifikatori

Javob parametrlari

ParametrTuriTavsif
transactionStringTa'minotchi tranzaksiya ID (CreateTransaction javobidan)
perform_timeTimestamp (ms)Bajarilgan vaqt
stateIntegerHar doim 2 (bajarilgan)

State o'tish

state: 1 → state: 2

Ta'minotchining majburiyatlari

  1. Tranzaksiyani DB da topish (id bo'yicha) — yo'q bo'lsa -31003
  2. Tranzaksiya state ini tekshirish:

    • state=2 → idempotentlik — avvalgi perform_time qaytarish
    • state=-1 yoki -2 → -31008
  3. Foydalanuvchi balansini oshirish / buyurtmani to'langan qilish
  4. state=2, perform_time=now qilib saqlash

  "id": 3

To'lovni boshlash — GET so'rov (URL)

Foydalanuvchini Payme checkout sahifasiga yo'naltirish uchun eng oddiy usul — base64-kodlangan URL.

URL formati

GET https://checkout.paycom.uz/BASE64_PARAMS

Parametrlar

ParametrMajburiyTavsif
mHaKassa ID (merchant_id) — 24 belgili hex
ac.<field>HaAccount field(lar). Masalan: ac.order_id=ORD-123
aHaSumma (tiyinda)
lYo'qTil: ru, uz, en
cYo'qTo'lov tugagandan keyin qayta yo'naltirish URL (callback)
ctYo'qCallback timeout (ms)
crYo'qTijorat valyutasi: 860 (UZS), 840 (USD)

Kodlash qoidalari

  1. Parametrlarni ; (nuqta-vergul) bilan ajrating
  2. Har bir parametr key=value shaklida
  3. Olingan stringni base64 kodlang
  4. Natijaviy stringni URL oxiriga qo'shing

Misol

Parametrlar:

m=5e730e8e0b852a417aa49ceb;ac.order_id=ORD-123;a=500000;l=uz;c=https://example.uz/return

Base64 qilingan:

bT01ZTczMGU4ZTBiODUyYTQxN2FhNDljZWI7YWMub3JkZXJfaWQ9T1JELTEyMzthPTUwMDAwMDtsPXV6O2M9aHR0cHM6Ly9leGFtcGxlLnV6L3JldHVybg==

To'liq URL:

https://checkout.paycom.uz/bT01ZTczMGU4ZTBiODUyYTQxN2FhNDljZWI7YWMub3JkZXJfaWQ9T1JELTEyMzthPTUwMDAwMDtsPXV6O2M9aHR0cHM6Ly9leGFtcGxlLnV6L3JldHVybg==

JavaScript misoli

function buildPaymeCheckoutUrl(merchantId, amount, accountField, accountValue) {
  const params = [
    `m=${merchantId}`,
    `ac.${accountField}=${accountValue}`,
    `a=${amount}`,
    `l=uz`,
    `c=https://example.uz/return`,
  ].join(';');

  const encoded = btoa(params);
  return `https://checkout.paycom.uz/${encoded}`;
}

const url = buildPaymeCheckoutUrl(
  "5e730e8e0b852a417aa49ceb",
  500000,
  "order_id",
  "ORD-123"
);
// window.location.href = url;

Subscribe API — Umumiy ko'rinish

Subscribe API Merchant API ga aksincha yo'nalishda ishlaydi: ta'minotchi Payme ga so'rov yuboradi, Payme javob qaytaradi.

Merchant API vs Subscribe API

XususiyatMerchant APISubscribe API
Yo'nalishPayme → Ta'minotchiTa'minotchi → Payme
AuthAuthorization: Basic ...X-Auth: id:key
MaqsadWebhook (Payme o'zi so'raydi)Chek yaratish, kartani tokenlash
Billing talab qiladimiHa (buyurtma bazasi)Yo'q
Takroriy to'lovYo'qHa (token bilan)

URL

MuhitURL
Sandboxhttps://checkout.test.paycom.uz/api
Productionhttps://checkout.paycom.uz/api

Avtorizatsiya — X-Auth header

FormatQachon
X-Auth: <id>Frontend (karta tokenlash)
X-Auth: <id>:<key>Backend (server-to-server)

Bu yerda id — kassa ID (merchant_id), key — kassa kaliti.

Xavfsizlik — karta tokenlash

Muhim: Ta'minotchi karta ma'lumotlarini (karta raqami, CVV, muddat) saqlab bo'lmaydi. Bu PCI DSS qoidalarini buzadi.

O'rniga:

  1. Foydalanuvchi kartani kiritadi → Payme'ga yuboriladi → Payme token qaytaradi
  2. Ta'minotchi faqat token ni saqlaydi
  3. Keyingi to'lovlarda token orqali chek yaratiladi

Karta kiritish formasi talablari

  • Payme logotipi ko'rsatilishi shart
  • Foydalanish shartlari havolasi
  • "Ma'lumotlar ta'minotchiga yuborilmaydi, Payme serverida saqlanadi" degan eslatma

Jarayon diagrammasi

Subscribe API ketma-ketlik diagrammasi

1. Foydalanuvchi: Karta raqamini kiritadi (ta'minotchi saytida)

2. Frontend → Payme API: cards.create (X-Auth: id)

3. Payme → Frontend: karta tokeni

4. Frontend → Backend: tokenni saqlash uchun yuboradi

5. Backend: tokenni DB'ga yozadi

6. To'lash vaqtida: Backend → Payme API: receipts.create

7. Backend → Payme API: receipts.pay (token bilan)

8. Payme: Kartadan pulni yechadi

Mobil integratsiya

iOS va Android ilovalarida Payme to'lov integratsiyasi — deeplink orqali.

Umumiy yondashuv

Mobil ilova Payme checkout URL ni tizim brauzeri yoki o'rnatilgan Payme ilovasi orqali ochadi:

  • Agar Payme ilovasi o'rnatilgan → avtomatik o'sha ochiladi
  • Agar yo'q → Safari/Chrome'da checkout sahifa ochiladi

val url = "https://checkout.paycom.uz/$base64Params"

startActivity(intent)

fun buildPaymeParams(m: String, amount: Long, orderId: String): String {
    val params = "m=$m;ac.order_id=$orderId;a=$amount;l=uz"
    return Base64.encodeToString(
        params.toByteArray(Charsets.UTF_8),
        Base64.NO_WRAP
    )
}

Telegram bot orqali to'lov

Payme Business Telegram bot orqali chek yaratish va to'lov qabul qilishni qo'llab-quvvatlaydi.

Ish jarayoni

  1. Sizning Telegram bot'ingiz foydalanuvchiga buyurtma tafsilotini ko'rsatadi
  2. "To'lash" tugmasi bosilganda Payme checkout URL yuboradi
  3. URL ochilganda — brauzer yoki Payme ilovasi orqali to'lov amalga oshiriladi
  4. To'lov tugagach — webhook orqali botga xabar beriladi

Telegraf / grammY misoli (Node.js)

bot.command('pay', async (ctx) => {
  const amount = 500000;
  const orderId = `ORD-${ctx.from.id}-${Date.now()}`;

  const params = `m=${MERCHANT_ID};ac.order_id=${orderId};a=${amount};l=uz`;
  const base64 = Buffer.from(params).toString('base64');
  const url = `https://checkout.paycom.uz/${base64}`;

  await ctx.reply('To'lov uchun havola:', {
    reply_markup: {
      inline_keyboard: [[
        { text: "Payme orqali to'lash", url }
      ]]
    }
  });
});

Telegram rasmiy to'lov API

Telegram sendInvoice metodida Payme provider tokenini qo'llab-quvvatlaydi. Bu holda to'lov Telegram ichida bo'ladi, tashqi havola kerak emas.

bot.telegram.sendInvoice(chatId, {
  title: "Matematika kursi",
  description: "1-oy uchun to'lov",
  payload: "ORD-123",
  provider_token: PAYME_PROVIDER_TOKEN,
  currency: "UZS",
  prices: [{ label: "Kurs", amount: 500000 }]
});
PAYME_PROVIDER_TOKEN — Payme Business bilan alohida shartnoma tuzilganidan so'ng beriladigan token. Oddiy kassa kalit emas.
