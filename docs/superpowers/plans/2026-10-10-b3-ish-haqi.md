## Decisions (where the spec leaves a choice)

1. **`planAdvanceNetting` lives in `server/src/salary/shared/advance-netting.ts`** and is the only walk over advances: the cron settles exactly `plan.settle`, the report shows exactly `plan.total`.
2. **The row's `advances` for a month with a payment = `grossAmount − amount`** of the merged payments (the settled advances), already computed in `paymentByUser`. No second query.
3. **Single-user calls carry more.** When `getMonthly` runs with `userId` (i.e. `getMonthlyForUser`), each row also returns `groups` (teacher buckets) and `advanceItems` (the advances the row's `advances` sums). The page's list call stays small.
4. **Group buckets skip carried-in accruals** (`creditPeriodDate` set); the drawer shows them as «Oldingi oydan — X». So Σ `groups[].amount` + `carriedIn` = `fullDeserved` (test).
5. **`GET /salary/advances/:userId` is removed** with `getAdvancesForUser` and `SalaryAdvanceBreakdownDrawer`: the row drawer lists the advances from the detail endpoint. Its snapshot row and manifest entry go.
6. **The detail and lessons routes take `@BranchScope()`** like `/salary/monthly` (the drawer opens from the page and must follow the header). A person outside the scope → 404 «Bu oyda xodim topilmadi».
7. **The cash accounts for «Berildi» come with the detail answer** (`cashAccounts`: the payee `mainBranch`'s active, not-deleted accounts, id/name/type). No call to `GET /cash-accounts`.
8. **Single pay writes its own Serializable transaction** (re-read → `recordSalaryPayment` with `cashSlices` → PAID with the chosen day), not `writeSettledRows`, so the ledger keeps «Oylik to'landi» and no settle marker goes into `note`. A 0 so'm payment (advances took everything) moves no money: no ledger row, just PAID.
9. **`notified` in the pay response** = the payee has a `telegramChatId` (the send itself is async). The toast reads it.
10. **`SalarySettleAllocatedService` emits nothing** (script-only, past months).
11. **Staff without a salary** is computed only when the call has no `search` and no `userId`.
12. **Tab amounts:** «Avanslar · X» = the month's advance-calendar total; «Markaz qoplagani · X» = the center-topup outstanding total of the whole period. Each hidden while loading or when 0.
13. **Short money in the summary** uses the B1 overview helper (`client/src/components/payments/overview/overview-math.ts`); tables use `formatPrice`.

```ts
/**
 * The one walk over a person's unsettled TEACHER_ADVANCE expenses (ADR-0082).
 * The payroll cron settles exactly `settle`; the salary report shows exactly
 * `total` as «Avans (oylikdan ushlanadi)», so the screen equals the deduction.
 *
 * Only advances dated before the period's exclusive end count (an advance given
 * on the 1st belongs to the new month even if the cron has not run yet). Walk in
 * `createdAt` order (id breaks ties) and stop at the first one that does not fit
 * into what is left of `grossAmount`; the rest roll over to the next month.
 * `Expense.date` is `@db.Date` (UTC midnight), so `periodEndDateExclusive` must
 * be the `@db.Date`-shaped bound, not a Tashkent-shifted instant.
 */
export interface PendingAdvance { id: string; amount: number; date: Date; createdAt: Date }
export interface AdvanceNettingPlan { settle: string[]; total: number }

export function planAdvanceNetting(pending: PendingAdvance[], grossAmount: number, periodEndDateExclusive: Date): AdvanceNettingPlan {
  const end = periodEndDateExclusive.getTime();
  const ordered = pending
    .filter((a) => a.date.getTime() < end)
    .sort((a, b) => a.createdAt.getTime() - b.createdAt.getTime() || a.id.localeCompare(b.id));
  const settle: string[] = [];
  let total = 0;
  for (const a of ordered) {
    if (total + a.amount > grossAmount) break;
    settle.push(a.id);
    total += a.amount;
  }
  return { settle, total };
}
```
