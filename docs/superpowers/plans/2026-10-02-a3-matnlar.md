# A3 «Matnlar» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the screens, Excel, PDF and Telegram texts speak the monthly billing model (since 2026-09) and plain Latin-script Uzbek. This covers spec A3 items 2–6 in `docs/superpowers/specs/2026-09-27-oylik-tizim-moliya-tuzatishlari-design.md`.

**Architecture:** Most tasks replace user-visible strings in place.

Two tasks carry logic:
- **Task 4:** the student's Telegram attendance counter reads the student's own monthly charge (`EnrollmentMonthlyCharge.coveredDates`).
- **Tasks 6–7:** the enrollment dialog shows the first month's prorated charge. The server gets a read-only preview built from the same computation as the real charge: `MonthlyChargeService.planChargeAmounts`, extracted from `createChargeForEnrollment`. The client then only renders it.

**Tech Stack:** NestJS 11 + Prisma 7 + Jest (`server/`); Next.js 16 + React Query + Vitest (`client/`).

**Scope notes (decided, do not reopen):**
- **A3.1 (salary split) is NOT done.** The spec (27.09) wanted one «Hisoblangan» figure in monthly months. On 29.09 the CEO chose the opposite: ADR-0052 keeps the «O'quvchilar to'lagan / Markaz qo'shdi» split and moves a charge's unpaid share into the centre column. That decision stands.
- **Not in this plan:**
  - the student app strings (separate release);
  - stored ledger reasons «Cascade: …» (old rows stay, and `statements/statement-months.ts` regex-matches them);
  - DTO enum validation messages;
  - unwired Excel builders (`kpiSheet`, `perBranchSheet`, …);
  - the pack-era features that still cut monthly enrollments into 12-lesson «sikl» blocks: the lesson trail tab, the attendance «Qarzdorlar» panel and the «yo'qolgan o'quvchi» write-off. Those need logic, not wording, and get a separate task.
- «Status» stays: it is a standard Uzbek loanword.

## Global Constraints

- All user-visible text is Latin-script Uzbek with no English words. Use the exact replacement strings each task lists.
- The pack model's own name «Sikl» / «Sikl to'lovi (dars-paket)» stays (Uzbek), and so do pack-only texts on pack-only branches.
- Every money figure on screen comes from the server; the client computes none.
- The first-month charge has ONE computation: `MonthlyChargeService.planChargeAmounts`, shared by `createChargeForEnrollment` and the preview. Do not write a second copy.
- A test that pins a string changes in the same commit as the string.
- Never run `prettier` on `client/`. Run `npx prettier --write` on every touched server file.
- `npm run typecheck` (server) type-checks specs; ts-jest is transpile-only.
- Client tests: from `client/`, run `npx vitest run <path>`.
- Commit messages are Latin-script Uzbek and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Code comments match the surrounding file's language. `CLAUDE.md` is English.
- No production database access. No push, PR, merge or deploy without the user's go.
- The client deploys before the server. A new client must work against the old server: where a new field is missing, fall back to today's wording or show nothing, and never crash.

### Task 4: Telegram attendance counter counts the month

**Files:**
- Modify: `server/src/attendance/student-attendance-notification.listener.ts` (≈:71-106)
- Test: `server/src/attendance/student-attendance-notification.listener.spec.ts`

Today the message prints `📊 <b>Dars:</b> N / 12`:
- N is every attendance row of the student in the group, ever.
- 12 is `course.lessonPaymentCount`.

For a MONTHLY course it must count the lesson within the student's own month. Take the student's CHARGED `EnrollmentMonthlyCharge` rows for this group and the lesson's month, and find the one whose live dates include the lesson date. Live dates are `coveredDates` minus `frozenOutDates`; they come from `lessonDatesInMonth`, so they are sorted. Then:
- N = position of the date in the live dates + 1;
- total = number of live dates.

If no charge covers the date, omit the «Dars:» line. LESSON_PACK courses keep today's behaviour exactly.

Sketch (fit it into the listener's existing flow):

```ts
// course select gains paymentModel
course: { select: { lessonPaymentCount: true, paymentModel: true } },

let lessonNumber: number | null = null;
let totalLessons: number | null = null;
if (group?.course?.paymentModel === PaymentModel.MONTHLY) {
  const [y, m] = date.split('-').map(Number);
  const charges = await this.prisma.enrollmentMonthlyCharge.findMany({
    where: {
      studentId,
      groupId,
      periodYear: y,
      periodMonth: m,
      status: MonthlyChargeStatus.CHARGED,
    },
    select: { coveredDates: true, frozenOutDates: true },
  });
  for (const c of charges) {
    const out = new Set(c.frozenOutDates ?? []);
    const live = (c.coveredDates ?? []).filter((d) => !out.has(d));
    const i = live.indexOf(date);
    if (i >= 0) {
      lessonNumber = i + 1;
      totalLessons = live.length;
      break;
    }
  }
} else {
  const count = await this.prisma.attendance.count({
    where: { studentId, groupId, date: { lte: parsedDate } },
  });
  lessonNumber = count > 0 ? count : null;
  totalLessons = group?.course?.lessonPaymentCount ?? null;
}
```

```ts
    coveredLessons: number;
    amount: number;
  } | null;
  /** The student's balance now; negative is a debt. */
  balance: number;
  /** max(0, due − balance); due = firstMonth.amount (MONTHLY, 0 when null) or coursePrice (pack — today's dialog rule). */
  payable: number;
}
```

**`previewChargeForNewEnrollment`:**

```ts
/**
 * What `createChargeForEnrollment` would charge an enrollment that does not
 * exist yet: the same plan, the same proration, the same discount. A new
 * enrollment has no excused-lesson credit to carry, so the amount is the
 * discounted, prorated price. Writes nothing; null when nothing would be
 * charged.
 */
async previewChargeForNewEnrollment(db, params) {
  const enr = params.enrollment;
  if (enr.group.course.paymentModel !== PaymentModel.MONTHLY) return null;
  if (enr.group.statusEnum !== GroupStatus.ACTIVE) return null;
  const planned = await this.planChargeAmounts(
    db,
    enr,
    params.periodYear,
    params.periodMonth,
    clampDiscount(params.discountPercent ?? 0),
  );
  if (!planned) return null;
  return {
    plannedLessons: planned.plannedLessons,
    coveredLessons: planned.coveredLessons,
    amount: planned.grossAmountStudent,
  };
}
```
